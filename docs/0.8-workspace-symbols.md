# 0.8 Design: LSP workspace symbols

Status: **implemented** — `workspace/symbol` with a query list and jump via the existing definition path.

## Intent

Jump to a named symbol anywhere in the language server’s workspace without becoming a full IDE. Reuse `OpenFileFromPath` + `GoToMatch` from Go to Definition / Find References.

**Success:**

- Find → Go to Symbol in Workspace / `Ctrl+T` / command palette.
- Query prompt is prefilled with the word at the caret (empty query is allowed).
- Hits are capped (200). One hit jumps immediately; several open a list (name, container, file:line).
- Missing / unsupported servers: status message, no crash.
- Outline (`Ctrl+Shift+.`) stays current-document `textDocument/documentSymbol`.

## Scope

| In | Out |
| --- | --- |
| `workspace/symbol` (SymbolInformation and WorkspaceSymbol) | `workspaceSymbol/resolve` |
| Query prompt + results list + jump | Peek / side-by-side |
| Menu + palette + `Ctrl+T` | Lightbulb, `executeCommand` |
| Soft-fail when the server omits `workspaceSymbolProvider` | Fuzzy ranking beyond the server’s list |

## Approach

1. Advertise `workspace.symbol` on initialize; record `workspaceSymbolProvider` (boolean or options).
2. `LspNavigationParser.ParseWorkspaceSymbols` for `SymbolInformation[]` / `WorkspaceSymbol[]`. Uri-only locations (no range) open at origin; `workspaceSymbol/resolve` is skipped.
3. `GoToSymbolQueryWindow` (prefilled from the caret); `WorkspaceSymbolsWindow` for multiple hits.
4. Unit tests with frozen JSON (no live language server).
