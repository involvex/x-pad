# 0.6 Design: LSP code actions (text edits)

Status: **implemented** — `WorkspaceEdit` text edits, including `codeAction/resolve` when the server omits `edit` until follow-up.

## Intent

Expose `textDocument/codeAction` for quick fixes / refactors that return edits, without `executeCommand` or workspace file create/rename/delete.

**Success:**

- `Ctrl+.` lists actions for the caret/selection (diagnostics from the selected tab when available).
- Choosing an action with an edit applies it to open buffers (or writes closed files via `FileService`).
- Actions that omit `edit` until `codeAction/resolve` are resolved when the server advertises `resolveProvider`.
- Command-only actions stay listed but are skipped with a status message.
- Missing / unsupported servers: status message, no crash.

## Scope

| In | Out |
| --- | --- |
| `textDocument/codeAction` + `WorkspaceEdit` (`changes` / `documentChanges` text edits) | `executeCommand`, create/rename/delete files |
| `codeAction/resolve` for the `edit` property when `resolveProvider` is set | Lightbulb gutter UI |
| Menu + palette + `Ctrl+.` | |
| Pass current-tab diagnostics in context | |

## Approach

1. `LspCodeAction` / parser / `LspWorkspaceEditApplier` (newest-first offsets; `Func<path, TextDocument?>`); keep raw action JSON for resolve.
2. `LspClient.CodeActionsAsync` + `ResolveCodeActionAsync` + `resolveSupport` / `resolveProvider` on initialize.
3. `CodeActionsWindow` + `MainWindowViewModel.ShowCodeActions` (resolve when the pick has no edit).
4. Unit tests for parser + apply-to-document order + data-only / resolved payloads.
