# 0.7 Design: LSP rename symbol

Status: **implemented** — `textDocument/prepareRename` + `textDocument/rename` with WorkspaceEdit text edits via the existing applier.

## Intent

Rename the identifier at the caret through the optional language server, without becoming a full IDE. Reuse the `WorkspaceEdit` path from code actions (`LspWorkspaceEditApplier`).

**Success:**

- Find → Rename Symbol / `Ctrl+Shift+R` / command palette prompts for a new name.
- When the server advertises `prepareProvider`, prepare supplies the range / placeholder; otherwise the word at the caret is used.
- The resulting text edits apply to open buffers and to closed files via `FileService`.
- Create/rename/delete file operations in the edit are skipped (same as code actions).
- Missing / unsupported servers: status message, no crash.
- F2 / Ctrl+F2 / Shift+F2 stay bookmarks (Notepad++ daily-driver).

## Scope

| In | Out |
| --- | --- |
| `textDocument/prepareRename` + `textDocument/rename` | `workspace/executeCommand` |
| WorkspaceEdit text edits (`changes` / `documentChanges`) | CreateFile / RenameFile / DeleteFile |
| Menu + palette + `Ctrl+Shift+R` | Remapping F2 to rename |
| Soft-fail when prepare rejects or rename returns no edits | Peek rename UI / lightbulb |

## Approach

1. Advertise `textDocument.rename.prepareSupport` on initialize; record `renameProvider` / `prepareProvider`.
2. `LspNavigationParser.ParsePrepareRename` for Range / `{ range, placeholder }` / `{ defaultBehavior }` / null.
3. `RenameSymbolWindow` (Go to Line–style) + `MainWindowViewModel.RenameSymbol` → `LspWorkspaceEditApplier.ApplyAsync`.
4. Unit tests with frozen JSON (no live language server).
